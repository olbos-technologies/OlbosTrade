## Unreleased — Stop booking held positions as closed on a hollow position list

- The fill-polling loop no longer books a trade closed with unknown P&L (`closed_price_unavailable`) just because the broker's local position cache stopped listing it. Before that destructive step it now asks IBKR over the network (`confirm_symbol_flat`); only an affirmative "flat" closes the row. If the broker still holds the position, cannot answer, or errors, the row stays open, an error is logged once per episode (`poll_fills.close_held_unconfirmed` counter) and it is re-checked every cycle. Cause: on 2026-11-07 AMZN, FER and SPCX were booked closed 23 ms apart while still held. Rows closed from a real execution price are unchanged. Backend restart needed; no migration, no new environment variables. A row for a position that really is gone but that the broker cannot confirm flat must be closed manually.
