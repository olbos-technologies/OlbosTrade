## Unreleased — Market breadth calculation and report (read-only)

- New `backend/app/services/market_breadth.py`: the share of a stock universe trading above its own 50-day average each day, with an 8-day and a 200-day line of that share, a plain-words state (`washout` under 40%, `weak` under 50%, `healthy`, `extended` from 70%, or `unknown`), and peaks and troughs found in hindsight. Pure arithmetic: it imports no broker, network or execution code (a test guards this).
- It refuses to look healthy on thin data: fewer than 30 names, or fewer than 80% of the asked-for names having a price on the latest day, gives `unknown` with the reason, and a symbol that returned nothing still counts against coverage. Missing prices are never counted as "below". Turning points are never reported in the newest bars, because they cannot be confirmed yet.
- New `backend/scripts/market_breadth_report.py` (run on the server): fetches daily closes the same way the other study scripts do, prints the latest reading, the last 10 days, the turning points and how many washout days there were, and can write a CSV. The default universe is about 90 liquid large caps, a proxy for the market and not the S&P 500 (the printout says how many names were really used; `--universe FILE` takes a wider list). It writes nothing to the database.
- This describes the market. It is not a signal and nothing reads it: no risk, sizing or order path uses it. Whether it improves our trades is for the Edge Lab ledger to test first.
- Backend only: no migration, no new environment variables, no restart needed (nothing is wired in yet). The script needs network access to Yahoo, which the Claude sandbox does not have, so it has only been run against synthetic prices; the first real run is on the server.
