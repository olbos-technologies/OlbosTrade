## Unreleased — EmotionGuard's pause and loss count now survive a restart

- `EmotionGuard` blocks entries for eight hours after four consecutive losses (or tilt) and was written to survive a restart, but it persists by updating the latest `portfolio_snapshots` row and nothing ever inserted one, so the table has been empty for the life of the feature and every restart — which is how this system is deployed — reset the pause and the loss count. A scheduler job now writes a snapshot every 10 minutes from the guard's own state. It refuses to write from an unmeasured account value, an unreadable P&L history, or a guard whose saved state was never loaded, so a fabricated or fresh-start value cannot overwrite a real pause. `rehydrate_from_db` now merges (keeping the more restrictive of memory and database) and reports whether the read succeeded. No migration, no new environment variable; adds roughly 144 small rows a day.
