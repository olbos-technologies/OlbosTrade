## Unreleased — Options signal timing report (read-only script)

- New operator script `backend/scripts/options_signal_timing_report.py`: for each score band (below 0.62, 0.62–0.70, 0.70 and above) it shows how many options signals were generated inside versus outside regular trading hours (09:30–16:00 ET, Mon–Fri, using the app's own market-hours rule), the Eastern-time hour the 0.70-and-above signals appeared in, and what happened to each of those signals (the first options execution attempt for the same ticker within 30 minutes: submitted, or the recorded refusal reason; otherwise a Copilot approval request; otherwise "no attempt or approval recorded"), split by whether the signal was generated in regular hours and showing when each outcome was last seen, so an old problem can be told from a current one. It also lists the execution-mode changes on record and tallies the 0.70-and-above signals by the mode in force when each was generated (a signal generated in MANUAL mode is recorded and nothing else happens, so "no attempt" is expected there). It compares the top band's in-hours share with the other bands only when each has at least 30 signals, and otherwise says "insufficient data". It only reads the database: no writes, no orders, no change to any limit or threshold. Run it on the server with `python scripts/options_signal_timing_report.py --days 90` inside the backend container. Backend-only; no restart, no migration, no new environment variables.
