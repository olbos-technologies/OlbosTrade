## Unreleased — An unreadable P&L history blocks entries instead of reading as zero

- When the database read for P&L and the loss/trade counters failed, `/api/guardrails/status` substituted zeros and carried on, so the daily-loss, weekly-loss, monthly-loss, consecutive-loss and daily-trade-cap limits all silently passed. It now blocks with its own reason (`pnl_unknown`: "the P&L is unknown, not zero") and logs the exception type. This is the mirror image of the 2026-10-31 failure, where a failed *account* read fabricated an 81.82% drawdown; here a failed *P&L* read fabricated safety. Fails closed.
- Guardrail audit rows no longer record a substituted value as the portfolio value: an unknown account value is stored as NULL, where it previously wrote `STARTING_CAPITAL` — the source of `50000.0000` on every fabricated-drawdown row. `account_value_unknown` and `pnl_unknown` are also registered as suspend events so a restart seeds the right state. No limit or threshold changed; no migration.
