## Unreleased — Research script: fixed take-profit / stop-loss geometries on identical entries

- New read-only `backend/scripts/fixed_exit_geometry_study.py`. It reads the same 5-minute bars CSV as `vwap_reversion_backtest.py` (from `intraday_bars_fetch.py`) and compares exit geometries on IDENTICAL entries: A 0.5% take / 1.0% stop (the proposal), B 0.5/0.5, C 0.5/0.25, D 1.0/0.5, and E volatility-scaled (1.0x take, 1.5x stop of the symbol's hourly-equivalent ATR). Entries are a null set (a long every 30 minutes, no signal in it) and one example real rule (opening-range breakout), so the exit rule's own effect can be told apart from the entry's.
- It reuses the existing simulator and its conservative conventions: entry at the next bar's open plus slippage, the stop is assumed to fill first when a bar touches both, a bar that opens beyond the stop fills at the open (a gap loses more than the stop promised), a target must trade through by one tick, commission on both sides, everything flat by 15:55 ET.
- The report gives per geometry: trades, win rate, the break-even win rate for that geometry (0.5/1.0 needs two wins in three before costs), mean net result per trade after costs with a bootstrap 95% range, dollars per trade on the notional, the first-half and second-half means, and how trades exited. Fewer than 30 trades prints INSUFFICIENT DATA instead of a mean. Nothing in it is a forecast or a verdict.
- It writes nothing, places nothing, and imports no broker, database or execution code (a test guards this). No production exit setting changes: the current equity stop (2x ATR) and target (4x ATR) are untouched.
- Backend script only: no migration, no new environment variables, no restart. Run it on the server with the bars CSV; the sandbox has no market data, so it has only been run on synthetic bars.
